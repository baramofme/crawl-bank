# 조회(Extraction) 연구 계획

> 로그인 성공 후 계좌 조회 → 거래내역 추출(CSV)까지의 연구 내용과 진행 상황 기록.
> **로그인이 아직 완료되지 않아(보안 프로그램 차단) 이 영역은 대부분 미탐색 상태.**

## 최종 목표

로그인 후, 등록된 계좌 목록에서 원하는 계좌를 선택해 조회하고, 거래내역을 파싱해 CSV로 저장하는 것.

```
1. 계좌조회 페이지 이동 (URL: #210101000000)
2. 계좌 목록 로드 (특정 계좌 목록으로 조회)
3. 조회 조건 선택 (기간 등)
4. 조회 실행
5. 거래내역 HTML 파싱 → CSV 저장
```

## 연구 항목

| # | 연구 항목 | 문서 | 상태 |
|---|-----------|------|------|
| 1 | 계좌 조회 (계좌 목록, 조건 선택) | `account-inquiry.md` | 🔴 미탐색 (기존 구현 일부 있음) |
| 2 | 거래내역 HTML 파싱 | `transaction-parsing.md` | 🔴 미탐색 |

## 기존 구현 현황 (login.js, 미검증)

| 함수 | 동작 | 상태 |
|------|------|------|
| `goToAccountPage()` | `#210101000000` URL로 이동 | 구현됨, 미검증 |
| `accountInquiry(accountNo, accountPw)` | 계좌번호/비밀번호 입력 + "조회" 버튼 클릭 | 구현됨, 미검증 (placeholder 기반 셀렉터라 실동작 확인 필요) |
| `selectThreeMonths()` | 3개월 기간 select 선택 | 구현됨, 미검증 |

## 팝업 UI 버튼 (popup.html)

```
3. 계좌조회 이동          → #goToAccount
4. 계좌 조회              → #doAccountInquiry (accountNo/accountPw 입력)
4-1. 조회기간 3개월 선택   → #selectPeriod
5. 거래내역 CSV 다운로드   → #downloadCsv
```

## 다음 세션의 첫 작업

1. 로그인 완료 후 `#goToAccount` 클릭 → 계좌조회 페이지 DOM 구조 캡처
2. 실제 계좌번호 입력/조회 동작 확인 (기존 셀렉터가 실제 페이지와 맞는지)
3. 거래내역 테이블 구조 파악 → 파싱 로직 설계
