# 연구: 거래내역 HTML 파싱

> 조회 결과로 나온 거래내역 테이블을 파싱해 CSV로 저장하는 방법.
> **상태: 🔴 미탐색** — 로그인/조회가 아직 완료되지 않아 실제 결과 페이지 구조를 확인 못 함.

## 목표

거래내역 테이블 → 구조화된 데이터 → CSV 파일 저장

```
날짜, 적요, 출금액, 입금액, 잔액  (필드는 실제 페이지 확인 후 확정)
```

## 연구해야 할 것

### 1. 결과 테이블 DOM 구조

- 거래내역 테이블의 실제 마크업 (thead/tbody 구조, w2ui 그리드 여부)
- w2ui 그리드(`.w2ui-grid`)인 경우: 데이터가 DOM에 있는지, JS 객체(`w2ui['grid'].records`)에 있는지
  - w2ui는 가상 렌더링이라 화면에 보이는 행만 DOM에 있을 수 있음 → **JS 객체 접근이 더 안전**
- 페이지네이션: 전체 내역이 한 페이지인지, 페이징/스크롤 로드인지

### 2. 파싱 방법 후보

| 방법 | 장점 | 단점 |
|------|------|------|
| DOM 테이블 순회 (`querySelectorAll('tr')`) | 단순 | w2ui 가상 렌더링 시 누락 위험 |
| w2ui 그리드 API (`w2ui['xxx'].records`) | 전체 데이터 접근 | w2ui 인스턴스 이름/구조 파악 필요 |
| XHR/AJAX 응답 인터셉트 | 원본 데이터 | 페이지가 어떤 요청을 하는지 분석 필요 |

### 3. CSV 변환

- 필드: 날짜/적요/출금/입금/잔액 (실제 페이지 확인 후 확정)
- 인코딩: 한글 포함 → UTF-8 with BOM (엑셀 호환)
- 금액: 숫자만 추출 (콤마 제거)
