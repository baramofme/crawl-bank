# 연구: 키패드 문자 인식 (VLM)

> 키패드 이미지에서 각 키의 영문/숫자를 인식해 charMap(문자 → 키 인덱스)을 만드는 방법.
> 목표: **가장 작고 빠른 모델로 높은 정확도** (한글 자모는 무시하고 영문만 추출).

## 최종 채택 방법 (정확도 34/36)

### 1. 개별 키 크롭 (행 스트립 아님)

- 행 스트립(한 줄 통째로 VLM 전송)은 **숫자 행을 영문으로 오인**하는 문제가 있어 폐기
  - 예: row1 숫자 `1,2,3...`이 `a,b,c...`로 인식됨
- **각 키를 개별 4x 크롭** → VLM에 한 번에 하나씩 질문
- 배치 4개씩 병렬(`Promise.all`) 처리 — 37키 기준 약 25~50초

### 2. ICON 키는 픽셀 감지로 제외

- 컬러 픽셀 비율 >5%인 키를 ICON(더미)으로 판정 → VLM 질문 대상에서 제외
- 위치가 세션마다 바뀌어도 항상 정확 (한 줄당 2개 고정은 확인용)

### 3. 모델 선정 (가장 중요)

| 모델 | 크기 | 정확도 | 속도 | 비고 |
|------|------|--------|------|------|
| Qwen2.5-VL-3B | 3.2GB | 26/36 | 느림 | 사용자: 너무 무거움 → 제외 |
| SmolVLM2-256M | 175MB | 11/36 | 빠름 | 영문 전멸, 프롬프트 문구 반복 — 실패 |
| **LFM2.5-VL-450M** | 379MB | **34/36** | 빠름(1.4s/키) | ✅ 채택. 숫자 10/10, 영문 대부분 |

### 4. LFM2.5-VL-450M 필수 파라미터

```json
{
  "max_tokens": 10,
  "temperature": 0.1,
  "min_p": 0.15,
  "repetition_penalty": 1.05
}
```

- **temperature 0, min_p 미설정 → 18/36** (영문 절반이 0/1로 오인)
- **위 파라미터 적용 → 34/36** (숫자 10/10, 영문 24/26)
- 누락 2개는 `o`(→h로 오인), `l`(→1로 오인) — 더미 비번 test345에는 불필요

### 5. 프롬프트는 짧게

- ❌ 긴 프롬프트("What character is displayed on TOP, ignore Korean below...") → 18/36
- ✅ 짧은 프롬프트 → 34/36:
  ```
  Output exactly one character shown in this image: a lowercase letter (a-z) or digit (0-9). Output nothing else.
  ```

### 6. 이미지 전처리

- 4x 업스케일: `imageSmoothingQuality = 'high'` (canvas) / `Image.LANCZOS` (PIL)
- h=20으로 상단 영문만 크롭 → **역효과** (모델이 "a"로 붕괴). 전체 키(h=38) 4x가 최적
- 대비 강화(autocontrast) → 역효과. 원본 그대로가 최적
- 응답 검증: `/["']?([a-zA-Z0-9])["']?/` 정규식으로 1문자만 추출, 중복 시 실패 카운트
